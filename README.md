# 株式会社エムビーエス 経費精算システム

現行の紙/Excel「立替/仮払経費精算書」をWeb化したもの。社員(約100名)が領収書をスマホカメラ/スキャナで**複数枚まとめて**取り込み、
部門コード・工事コード・支払内容を入力して精算書を作成、上長→経理の承認を経て精算します。
(リポジトリ名は `HAKOSHIP` ですが、エムビーエス案件です。GitHubの Settings → General で名称変更できます)

## 機能
- **精算書(1通=複数明細)**: 現行様式どおり、ヘッダ(申請日・所属・氏名)＋明細(部門コード・支払日・工事コード・支払先・支払金額・支払内容/目的)＋合計①・仮払金②・差引過不足額③(=②-①)
- **領収書の一括取り込み**: 写真/PDF/スキャンを複数選択(最大20枚)、またはカメラで1枚ずつ追加。1枚=1明細。同一領収書の重複はブロック。領収書のない明細(交通費等)も追加可
- **AI自動読み取り(任意)**: 支払日・金額・支払先・インボイス番号を自動入力(下書き入力のみ。必ず確認)
- **承認フロー**: 申請 → 上長承認 → 経理承認 → 精算済。各段階で差戻し(理由必須)。上長未設定なら経理へ直接。自己承認不可。全操作を履歴保存
- **経理**: 申請月・状況・工事コード・キーワードで絞り込み、**明細単位のCSV出力**(Excel対応)、一括「精算済」、現行様式に近い**印刷用表示**
- **管理者**: ユーザー(所属部門・承認者、CSV一括登録)、**部門マスタ**、**工事マスタ**(いずれもCSV一括登録可)
- **セキュリティ**: bcrypt、CSRF、ログイン試行制限、署名付きCookie、CSVインジェクション対策、画像再エンコード(EXIF位置情報除去)、領収書は権限者のみ閲覧

## 起動
```bash
python3 -m venv .venv && . .venv/bin/activate && pip install -r requirements.txt
python -m app.seed --admin-email you@example.com --admin-password '10文字以上のパスワード'
python -m app.seed --demo        # 開発用デモデータ(任意)
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
pytest                           # テスト
```
初回は管理画面で「部門」「工事」マスタを登録(CSV: `code,name`)し、ユーザーをCSV(`email,name,role,approver_email,department_code`)で一括登録してください。

## AI自動読み取り(Claude Vision)
領収書を選ぶと日付・金額・支払先・インボイス番号・勘定科目を自動入力します(**入力欄の初期値の提案のみ**。申請者が確認・修正し、入力済みの欄は上書きしません)。
- 有効化: 環境変数 `ANTHROPIC_API_KEY` を設定(未設定なら機能オフで従来の手入力)。モデルは `OCR_MODEL`(既定 `claude-haiku-5-5`)
- **AIが停止・遅延・エラーでも申請業務は止まりません**: 失敗時は「手入力してください」と表示するだけ。3回連続失敗で60秒AI呼び出しを停止し、画面が待たされないようにしています
- 注意: 領収書画像が Anthropic API に送信されます。社内のセキュリティ方針で許可されているか確認してください。複数枚取り込み時は同時4件まで並行して読み取ります

## 設定(環境変数)
`DATA_DIR`(DB・領収書の保存先, 既定 `./data`), `DATABASE_URL`(PostgreSQL等に変更可), `SECRET_KEY`, `COOKIE_SECURE=1`(HTTPS時は必須), `MAX_UPLOAD_MB`, `MAX_AMOUNT`。明細上限は `MAX_LINES`(既定50)。

## 本番運用の注意
- 必ず **HTTPS**(リバースプロキシ等)で公開し `COOKIE_SECURE=1` を設定。カメラ起動もHTTPS必須です
- `DATA_DIR` を定期バックアップ(DBと領収書画像)
- 電子帳簿保存法のスキャナ保存要件(タイムスタンプ、訂正削除の履歴、検索要件等)を満たすかは税理士・経理と要確認。現状は登録日時・ハッシュ・承認履歴・日付/金額/取引先検索(経理画面)を保持
- ログイン試行制限はプロセス内メモリのため、複数プロセス運用時は共有ストアが必要

## 保全(バックアップ)
- **コード**: GitHub(履歴付き)。push/PR のたびに GitHub Actions が自動テストします(`.github/workflows/ci.yml`)
- **業務データ(DB・領収書)**: GitHub には置かないでください(個人情報・会計情報)。`scripts/backup.sh` を cron で毎日実行し、**サーバーとは別の場所**(別ディスク/クラウドストレージ等)に保存します。既定で90日保持
  ```
  0 2 * * * DATA_DIR=/var/hakoship/data BACKUP_DIR=/mnt/backup/hakoship /path/to/scripts/backup.sh
  ```
- 復元: バックアップの tar.gz を展開し、`app.db` と `receipts/` を `DATA_DIR` に戻す。**年1回は復元テスト**を推奨
- 領収書は法定保存期間(原則7年)があるため、バックアップの保持期間は経理と相談して `KEEP_DAYS` を調整してください
